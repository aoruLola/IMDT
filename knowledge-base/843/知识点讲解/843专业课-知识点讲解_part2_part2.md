## 最小例题

**题**：浏览器输入域名到看到网页，DNS 和 HTTP 分别做什么？

**讲解**：
- 先查通讯录得到服务器地址。
- 再建立合适的传输连接/发送请求。
- 服务器返回响应，浏览器解析展示。

**答案**：DNS 把域名解析为 IP；HTTP 按应用协议请求和传输网页资源。

### 避坑

- 把 IP 地址、MAC 地址和端口号混用。
- 把 TCP 的可靠性误认为 IP 层提供。
- 背七层模型但不能解释一次真实请求。

### 考点用法

考试遇到“物理层：信号、信道、奈奎斯特定理、香农定理、传输介质、同步/异步传输”时，先圈出题目条件，再调用对应的定义、步骤或判断标准。

### 自测

**问**：为什么分层能降低网络系统复杂度？

**答**：每层通过清晰接口提供服务，内部实现可变化而不必让所有上层一起改变。

**解析**：分层把一个巨大问题拆成可替换的责任边界。

## 从现实生活发现问题：现象、痛点、矛盾、机会和未满足需求（843-125）

### 正式表达

矛盾是反映事物内部或事物之间对立统一关系的哲学范畴。矛盾具有普遍性和特殊性，分析问题要坚持具体问题具体分析，抓住主要矛盾和矛盾的主要方面。

$$
普遍性要求敢于承认矛盾；特殊性要求具体分析；主要矛盾决定工作重点，但不能否定次要矛盾。
$$

### 掌握要点

- 从现实生活发现问题
- 现象
- 痛点
- 矛盾
- 机会和未满足需求

### 掌握路径

1. 先找材料中的对立双方及其统一关系。
2. 再判断主要矛盾/主要方面和所处条件。
3. 最后提出有重点、分条件、可转化的解决思路。

### 最小例题

**题**：为什么‘牵牛要牵牛鼻子’体现主要矛盾方法？

**讲解**：
- 承认问题有多个矛盾。
- 判断哪一个对事物发展起主要作用。
- 重点突破，同时兼顾其他矛盾。

**答案**：它要求在复杂矛盾系统中抓住决定全局的主要矛盾，集中力量解决关键问题。

### 避坑

- 把主要矛盾说成唯一矛盾。
- 把矛盾特殊性背成固定标签，忽略条件变化。
- 把辩证法的矛盾和日常争吵等同。

### 考点用法

考试遇到“从现实生活发现问题：现象、痛点、矛盾、机会和未满足需求”时，先圈出题目条件，再调用对应的定义、步骤或判断标准。

### 自测

**问**：具体问题具体分析的‘具体’包括什么？

**答**：具体对象、具体条件、具体时间地点和矛盾发展的具体阶段。

**解析**：同一个原则在不同条件下的表现和解决办法可能不同。

## 区分“用户说要什么”和“用户真正需要什么”；识别目标用户、场景、任务和限制（843-126）

- 章节：创新设计类：四种官方能力 → A. 洞察力 ｜ 优先级：P0 ｜ 关键词：843、计算机基础、数据库、软件工程、AI、创新设计

### 学习目标

学完后，你能把设计答案写成‘用户—问题—机制—流程—验证—风险’的闭环，而不是堆概念。

### 问题与比喻

设计不是把界面装饰得好看，而是在约束下帮助某类人完成某个重要任务，并用证据证明方案有效。

> 类比：设计不是凭感觉画得好看，而是从真实问题出发，做出假设，再用原型和反馈不断验证。

### 正式表达

“区分“用户说要什么”和“用户真正需要什么”；识别目标用户、场景、任务和限制”要落到目标用户、具体场景、核心问题、设计机制、交互流程、评价指标和伦理边界。

### 掌握要点

- 区分“用户说要什么”和“用户真正需要什么”
- 识别目标用户
- 场景
- 任务和限制

### 掌握路径

1. 读题圈关键词：用户、场景、问题、限制、交付形式、评价标准。
2. 提出一个可验证的设计假设，画出最小流程或低保真原型。
3. 用完成率、时间、错误率、满意度或社会影响等指标验证，并说明风险。

### 最小例题

**题**：题目要求为老年人设计一个健康提醒功能，第一步做什么？

**讲解**：
- 目标用户不是‘所有老年人’，要具体到场景。
- 观察任务如何发生、哪里容易忘记或误操作。
- 再决定提醒方式、频率、反馈和异常处理。

**答案**：先定义真实使用场景和障碍，而不是马上画按钮；例如确认视力、记忆、设备使用和照护关系。

### 避坑

- 把用户说的功能直接当成真实需求。
- 只写创新口号，不写机制、流程和验证。
- 忽略无障碍、隐私、算法偏差和失败后的人工兜底。

### 考点用法

考试遇到“区分“用户说要什么”和“用户真正需要什么”；识别目标用户、场景、任务和限制”时，先圈出题目条件，再调用对应的定义、步骤或判断标准。

### 自测

**问**：一个完整设计方案至少要回答哪六个问题？

**答**：为谁设计、在什么场景、解决什么问题、用什么机制、如何验证、有什么风险/边界。

**解析**：六问齐全，答案才从‘想法’变成可落地、可评估的方案。

### 最小例题

**题**：TCP 和 UDP 的核心差别怎么说？

**讲解**：
- TCP 像需要签收的快递流程。
- UDP 像直接发出的小纸条。
- 选择取决于可靠性、时延和应用容忍度。

**答案**：TCP 面向连接并提供可靠、有序传输和流量/拥塞控制；UDP 无连接、开销小，但不保证可靠到达和顺序。

### 避坑

- 把 IP 地址和端口号当成同一种地址。
- 只背 OSI 七层名称，不会把协议放回职责。
- 把带宽、速率、吞吐量和时延混为一谈。

**解析**：DNS 像通讯录，HTTP 才是拿到地址后进行的应用层交流。

### 掌握要点

- 用户中心设计
- 设计思维
- 参与式设计
- 通用设计
- 无障碍设计

1. 记录真实场景、任务、障碍和动机，不急着给方案。
2. 把发现收敛成可验证的问题陈述和设计目标。
3. 用低成本原型验证关键假设，再根据证据迭代。

### 最小例题

**题**：用户说‘想要更多功能’，为什么不能直接加功能？

- 访谈只问意见，不问真实行为和过去经历。

**解析**：问题越具体，方案和评价指标越容易落地。
