# 数据库：把事实存得清楚、查得准确

## 843-sql | 从查询到分组：读懂SQL | SELECT；WHERE；JOIN；GROUP BY；HAVING；聚合；更新；事务

### 目标
能在纸上执行查询，区分筛行与筛组。

### 问题
想找借了至少2本未还书的人，为什么不能直接WHERE COUNT(*)>=2？

### 讲解
SQL是声明式查询语言：说明要什么结果，数据库选择执行方式。SELECT选输出列，FROM指定来源，JOIN…ON连接，WHERE先筛行，GROUP BY分组，HAVING筛组，ORDER BY排序。COUNT(*)计行；COUNT(column)忽略该列NULL；SUM、AVG等一般忽略NULL。逻辑理解顺序与书写顺序不同。INSERT新增，UPDATE修改，DELETE删除；写操作缺少WHERE可能影响所有行。事务把多步作为一个整体，成功提交COMMIT，失败回滚ROLLBACK。

### 推导
固定数据Loan=(id,reader_id,returned)：(10,1,0),(11,1,0),(12,2,1),(13,2,0)。先WHERE returned=0剩10、11、13；按reader_id分组得到1有2、2有1；HAVING COUNT(*)>=2仅保留1。事务的原子性防止借阅记录写入而库存未扣这种部分成功。

### 例题1
SELECT reader_id, COUNT(*) AS n FROM Loan WHERE returned=0 GROUP BY reader_id HAVING COUNT(*)>=2;
结果一行：reader_id=1,n=2。n是输出列别名，不是新增存储字段。

### 例题2
Reader=(1,小林),(2,小周),(3,小陈)。LEFT JOIN Loan可保留无借阅的3。统计每人借阅次数应COUNT(Loan.id)，结果1→2,2→2,3→0；COUNT(*)会把3的补NULL行也计1。

### 练习1
WHERE与HAVING可以不加区别互换吗？
提示：一个作用于行，一个作用于组。
解析：不能。聚合后的条件应HAVING；聚合前过滤可改变分组输入。

### 练习2
固定数据中COUNT(*)、COUNT(DISTINCT reader_id)各多少？
提示：完整Loan有四行，两位读者。
解析：分别4和2。若先筛未还，则行数3但不同读者仍2。

### 练习3
把用户输入直接拼进SQL字符串安全吗？
提示：输入可能被解释为语法。
解析：不安全。应用应使用参数化查询并配权限；字符串转义不能代替完整的安全设计。

### 回顾
先筛行，再分组，再筛组；输出几行要能手算。
